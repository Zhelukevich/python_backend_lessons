**Event Loop (Цикл событий)** — это «сердце» асинхронного программирования в Python (библиотека `asyncio`). 

Если продолжить тему предыдущего урока, то **Event Loop создан специально для решения IO-bound задач**. Он позволяет выполнять тысячи операций ожидания (сеть, база данных, файлы) внутри **одного потока** без блокировки программы.

---

### 1. Простая аналогия: Официант в ресторане

* **Синхронный подход (без Event Loop):** Официант подходит к Столику №1, берет заказ, идет на кухню и **стоит ждет**, пока повар приготовит блюдо (например, 20 минут). Всё это время Столик №2 сидит голодным и ждет официанта.
* **Асинхронный подход (Event Loop):** Официант — это **Event Loop**. Он берет заказ у Столика №1, отдает его на кухню (отправил запрос в БД) и **тут же идет** к Столику №2 принимать заказ. Когда повар кричит: «Заказ для столика №1 готов!» (событие завершения ввода-вывода), официант забирает блюдо и несет его клиенту.

---

### 2. Что такое Event Loop технически?

Event Loop — это бесконечный цикл, который занимается ровно двумя вещами:
1. **Следит за событиями** (например: пришел ответ от сервера, прочитался файл, сработал таймер).
2. **Переключает выполнение** между задачами, которые готовы к продолжению работы.

> Это называется **кооперативной многозадачностью** (*cooperative multitasking*). Задачи **сами добровольно** отдают управление Event Loop’у, когда уходят в ожидание (с помощью ключевого слова `await`).

---

### 3. Как устроен процесс (Пошагово)

```text
[ Очередь готовых задач ]  --->  [ EVENT LOOP ]  --->  [ Выполнение задачи ]
         ^                                                      |
         |                                                 Дошли до `await`
         |                                                 (ушли в ожидание IO)
         |                                                      v
  [ Событие наступило ]    <---  [ Системные часы / Сеть / Диск ]
  (Данные получены)
```

1. **Регистрация:** Вы создаете задачи (Tasks) и отдаете их в Event Loop.
2. **Выполнение:** Цикл берет задачу и выполняет её до первого слова `await`.
3. **Пауза:** На слове `await` (например, скачивание файла) задача говорит: *«Я жду данные из сети, вернись ко мне, когда они придут»*. Она засыпает и передает управление обратно в Event Loop.
4. **Переключение:** Event Loop не ждет! Он берет из очереди следующую готовую задачу.
5. **Возобновление:** Операционная система сообщает: *«Данные для первой задачи пришли!»*. Event Loop возвращает первую задачу в очередь, а затем продолжает её выполнение с того места, где она уснула.

---

### 4. Ключевые термины `asyncio`

Для работы с Event Loop нужно знать 4 понятия:

* **Корутина (Coroutine):** Функция, объявленная через `async def`. Её выполнение можно приостановить и возобновить.
* **`await`:** Оператор, который буквально означает: *«Приостанови эту функцию здесь, отпусти Event Loop заниматься другими делами, пока я жду результат»*.
* **Task (Задача):** Обертка над корутиной. Когда корутина заворачивается в Task (`asyncio.create_task`), она автоматически регистрируется в Event Loop и планируется к запуску.
* **Future:** Объект, представляющий результат, которого *еще нет*, но он появится в будущем (низкоуровневая вещь, база для `Task`).

### 5. Пример на коде: Как это выглядит

Сравним синхронный код и код с Event Loop.

```python
import asyncio
import time

# Имитация IO-bound задачи (например, сетевой запрос)
async def fetch_data(task_id, delay):
    print(f"Задача {task_id}: началась...")
    # await говорит Event Loop'у: "Я жду, займись другой задачей!"
    await asyncio.sleep(delay) 
    print(f"Задача {task_id}: ЗАВЕРШЕНА!")
    return f"Данные {task_id}"

async def main():
    # Создаем задачи и регистрируем их в Event Loop
    task1 = asyncio.create_task(fetch_data(1, 2)) # займет 2 сек
    task2 = asyncio.create_task(fetch_data(2, 3)) # займет 3 сек

    # Ждем завершения обеих задач
    await task1
    await task2

# ТОЧКА ВХОДА: Создает Event Loop, запускает main() и закрывает цикл в конце
start = time.time()
asyncio.run(main())
print(f"Все выполнено за: {time.time() - start:.2f} сек")
```

**Результат:**
```text
Задача 1: началась...
Задача 2: началась...
Задача 1: ЗАВЕРШЕНА!
Задача 2: ЗАВЕРШЕНА!
Все выполнено за: 3.00 сек
```
> **Синхронно** это заняло бы: $2 + 3 = 5$ секунд.  
> **Через Event Loop:** ровно 3 секунды (время самой долгой операции), так как они ждали одновременно.

### 6. Главное «Золотое правило» Event Loop

> ⚠️ **НИКОГДА НЕ БЛОКИРУЙ EVENT LOOP!**

Поскольку Event Loop работает в **одном потоке**, любая долгая синхронная операция остановит ВСЁ приложение для ВСЕХ пользователей:

❌ **Что сломает Event Loop:**
1. `time.sleep(10)` вместо `await asyncio.sleep(10)`. (Официант просто встал и замер на 10 секунд).
2. Синхронные библиотеки: использование `requests.get()` вместо асинхронного `aiohttp` или `httpx`.
3. **Тяжелые CPU-bound задачи:** Если запустить вычисление факториала от миллиона или сжатие видео внутри корутины, Event Loop зависнет, пока процессор не досчитает.

💡 **Что делать, если нужно решить CPU-bound задачу внутри асинхронного кода?**  
Выносить её в отдельный процесс или поток через `loop.run_in_executor()`:
```python
# Запуск синхронной тяжелой функции в отдельном потоке/процессе,
# чтобы не тормозить основной Event Loop:
loop = asyncio.get_running_loop()
await loop.run_in_executor(None, heavy_cpu_function, arg1)
```

### Резюме:
* **Event Loop** — диспетчер задач в одном потоке.
* Идеален для **IO-bound** (веб-серверы, чат-боты, парсеры).
* Бесполезен (и даже вреден) для чистых **CPU-bound** задач без использования пула процессов.
